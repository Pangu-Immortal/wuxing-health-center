## 一、结论先行
1. **"点击无反应"根因①（已修）**：`PopupManager.recycle` 的 Frequent 模式用 `removeFromParent()` 回收弹窗——节点脱离场景但仍存活且持有触摸监听，3.x 引擎 `PointerEventDispatcher._sortByPriority` 读残留 processor 的 `node.parent` 得 null 抛 `TypeError: Cannot read properties of null (reading 'parent')`，**中断整条触摸派发链，此后所有点击无反应**（四大面板均为 Frequent，每开关一次埋一颗雷）。修复：改为 `node.active=false`（停用不脱离，重显时 setParent 幂等、PopupBase.show 会 active=true）。
2. **"点击无反应"根因②（已修）**：manifest `sensorLandscape` 横屏 + 竖屏内容 → letterbox + 触摸坐标系错位（详见尺寸适配报告）。
3. **"白屏"三个来源（均已处置）**：①GameLogPanel 的 DOM 面板在 jsb 桩 document 上崩溃中断模块初始化（已用 hasRealDom 特征探测修复）；②模拟器 gfxstream 概率性启动 SIGSEGV（injectWebAssembly 阶段，二次启动恢复，模拟器特有，脚本已加 3 次启动重试）；③**误报**：monkey 随机事件打开 Play 商店"正在核对信息"系统页把游戏顶到后台（脚本已加 BACK+回前台再判定）。
4. **遍历结果**：3 轮 × 可视区控件（13/12/6 个）逐一点按，**19 次命中且状态变化、0 无响应、0 落空、0 崩溃、0 白屏**；SKIP=3 均为 `game/Canvas` 容器节点（无渲染组件、引擎 pick 不可拾取，属合理跳过）。
5. **monkey 600 事件压力**：进程存活、画面正常、JS 异常=0、E_Cocos=0、Fatal=0、ANR=0。

## 二、方法（为何不用 uiautomator）
Cocos 全屏渲染在单一 SurfaceView，uiautomator 只能看到 Activity 级节点，**看不到游戏内按钮**。故在游戏内嵌 `TouchDump` 埋点（`assets/script/common/component/TouchDump.ts`，经 GameSys 场景加载回调自动挂载）：
- `adb shell input keyevent 141`（F11，引擎 AndroidKeyCodes 仅映射到 F11）→ dump 全部可交互控件 `[TD-NODE] i= name=路径 rect=[世界包围盒]` + `[TD-STATE] canvas/design/visible`；
- 每次触摸冒泡到 Canvas 输出 `[TD-TOUCH] ui=(x,y) hit=命中路径`（证明点击到达引擎且命中谁）；
- adb 脚本按 `visible` 中心对齐映射 tap：`sx=(wx+VW/2)·(SCRW/VW)`、`sy=(VH/2−wy)·(SCRW/VW)`；
- 每控件点击前后各 dump 一次取 md5 对比判定"状态变化"；每控件点击后截图做白/黑屏像素检测；全程 logcat 落盘统计 JS 异常/Uncaught/Fatal/ANR。
- 注：`input.on(TOUCH_START)` 广播在 jsb 不触发，故监听 Canvas 节点冒泡（**不能挂场景根节点**——根 parent=null 会触发同一 _sortByPriority 崩溃）。
