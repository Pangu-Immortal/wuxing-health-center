# 五星卫生院 3.8.8 屏幕尺寸适配报告（对照原版 2.X）

日期：2026-10-17　方法：源码/配置/构建产物/真机（模拟器）四路取证后改造并复验

## 一、三项事实核对结论

### 事实①：原版 2.X 屏幕尺寸参数
| 参数 | 取值 | 位置 | 说明 |
|---|---|---|---|
| 设计分辨率 | **750 × 1334 设计像素**（竖屏基准） | `五星卫生院/assets/*.fire` 的 `cc.Canvas._designResolution`（loading.fire、game.fire 均为 750×1334） | 2.X 以设计像素为 UI 布局单位 |
| 适配策略（fit 标志） | **fitWidth=false、fitHeight=false（均未设）→ NO_BORDER** | 同上 `_designResolution` 无 fit 字段 | 等比缩放充满屏幕、对称裁切溢出边；贴边由 Widget 补偿 |
| Widget 贴边补偿 | game.fire 6 个、loading.fire 2 个，**全部四边对齐（_alignFlags=45）** | 场景文件 | 与 3.x 迁移后数量一致（实测 6/2 全 45），贴边机制可平移 |

### 事实②：原版打包与构建配置
| 参数 | 取值 | 位置 | 说明 |
|---|---|---|---|
| 发布方向 | **竖屏（webOrientation=portrait）** | `五星卫生院/settings/builder.json` | 实际发布产物为 web-mobile 竖屏 |
| 原生 orientation 字段 | landscape=true（**模板残留，与 webOrientation 自相矛盾**） | 同上 `orientation` | 原版未走原生打包，该字段未生效；3.x 误把它当真配置 |
| 资源打包 | inlineSpriteFrames=true、md5Cache=true、encryptJs+xxteaKey 存在 | 同上 | 2.X 图集内联/MD5 缓存/JS 加密机制 |
| 包名 | org.cocos2d.demo（默认值） | 同上 `packageName`/`android.packageName` | 未定制 |

### 事实③：真机最终呈现（原版）
- 竖屏充满；常见手机（9:16~9:19.5，宽高比 ≥ 750/1334）下 NO_BORDER 的缩放因子 = 屏高/1334，**横向可见区 = 750 设计像素满宽，无裁切**；
- 仅宽于 9:16 的屏（如平板竖屏 4:3）才出现横向对称裁切，由 Widget 四边对齐补偿贴边元素；
- 像素密度由引擎按设计分辨率自动换算，与 density 无关。

## 二、3.x 现状问题（改造前实测）
1. **方向冲突**：`native/engine/android/app/AndroidManifest.xml:8` 与 `instantapp/AndroidManifest.xml` 为 `sensorLandscape`（横屏）→ 模拟器横屏窗口 + 竖屏内容 = 左右大黑边 letterbox（2400×1080 截图实证，canvas 仅占中央 607px 宽）+ 触摸坐标系错位（引导点击无反应的直接原因之一）。
2. **fit 策略冲突**：`settings/v2/packages/project.json → general.designResolution` 为 fitWidth=true **且** fitHeight=true → SHOW_ALL（等比含入、留黑边），与原版 NO_BORDER 不一致。
3. **重复定义**：方向在 manifest（sensorLandscape）与 2.X 遗留 builder.json（landscape vs webOrientation=portrait）三处不一致；以"竖屏"为唯一真值统一。

## 三、改造清单（参数位置 / 改前 → 改后 / 作用）
| # | 文件:位置 | 改前 | 改后 | 作用 |
|---|---|---|---|---|
| 1 | `native/engine/android/app/AndroidManifest.xml:8` | `screenOrientation="sensorLandscape"` | `"portrait"` | 主 Activity 竖屏，与原版发布方向一致 |
| 2 | `native/engine/android/instantapp/AndroidManifest.xml` | 同上 | `"portrait"` | 即时应用同改 |
| 3 | `settings/v2/packages/project.json → general.designResolution` | `fitWidth:true, fitHeight:true`（SHOW_ALL） | `fitWidth:false, fitHeight:true`（**FIX_HEIGHT**） | 缩放因子=屏高/1334：常见竖屏手机与原版 NO_BORDER **完全等价**；宽屏（平板竖屏）由原版"纵向裁切"改为"横向扩展可见区"——不裁切、不留白、不拉伸，Widget 四边对齐补偿贴边 |
| 4 | 设计分辨率 | 750×1334 | **不变** | 与原版一致 |

统一后的唯一真值：**竖屏 + 750×1334 + FIX_HEIGHT + Widget 四边对齐贴边**。

## 六、遗留与说明
- 模拟器 gfxstream 存在概率性启动 SIGSEGV（injectWebAssembly 阶段，二次启动即恢复），为模拟器图形后端已知问题，与尺寸适配无关；真机不受影响（建议真机复验一次启动稳定性）。
- 2.X 的 encryptJs/xxtea 加密与 inlineSpriteFrames 在 3.x 无对应同名字段（3.x 用脚本加密插件与自动图集），如需对齐需另立任务，不影响尺寸呈现。


## 七、自纠（2026-10-17 12:40，全控件遍历阶段发现）
- 2.X Canvas 的 fit 标志为独立字段 `_fitWidth/_fitHeight`，实测 **均为 true = SHOW_ALL**（第一节表格"未设=NO_BORDER"为误读，已更正）。
- 因此 3.x 最终取值回退为 **fitWidth=true, fitHeight=true（SHOW_ALL，与原版完全一致）**：实测 visible=750×1334（设计区全可见、零裁切），letterbox 区由 Widget 四边对齐的背景拉伸填充，黑边像素=0。
- 此前 FIX_HEIGHT 方案在窄于 9:16 的屏（如 1080×2400，visible 实测 600×1334）会横向裁切 ±75 设计像素，违反"不裁切"要求，已弃用。
- 统一真值更新为：**竖屏 + 750×1334 + SHOW_ALL（同原版）+ Widget 四边对齐填边**。
