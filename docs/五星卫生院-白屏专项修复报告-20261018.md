# 五星卫生院 白屏问题专项修复报告

日期：2026-10-18　验证环境：Android 模拟器（1080×2400@420）debug APK + 浏览器预览
全量日志：/tmp/flow_logcat.log　巡检截图：/tmp/ws_*.png、/tmp/wsc_*.png

## 一、结论先行
"依然很多白屏"由**两个叠加根因**构成，均已修复并实测消除：
1. **引导镂空遮罩整屏粉白**（主因，出现频率最高）：`HollowOut` 的自定义 hollowout shader 材质在原生（jsb/gfxstream）渲染异常——mask 节点 Sprite 未获得有效材质时以默认材质渲染**整屏粉白半透遮罩**，盖住全部游戏内容。引导共 32 步、每步 change/rectTo 都触发一次 → 用户感知"很多白屏"。
2. **letterbox 空白带粉白**（次因）：SHOW_ALL 适配在窄屏（9:20）上下留 letterbox，暴露相机默认清屏色（粉白 218,192,177），占屏约 20%。

## 二、根因取证
| 证据 | 内容 |
|---|---|
| APK 引导截图 | 整屏粉白半透、内容隐约可见（=遮罩盖屏），浏览器同步骤截图完全正常 → 定位原生渲染路径 |
| 像素采样 | letterbox 带色=(218,192,177)=相机 clearColor；内容顶边=(109,96,89)、底边=(183,168,168) 为纯色可无缝延伸 |
| 排除项 | 启动期 12 次连启 0 白屏（GameLogPanel jsb DOM 崩溃此前已修）；loading 高频采样 0 白帧；面板开/关/翻页巡检 0 白屏 |

## 三、修复清单
| 文件 | 改动 | 对应根因 |
|---|---|---|
| common/component/effects/HollowOut.ts | 原生端（JSB）跳过自定义 shader 材质路径：**禁用 mask 节点 Sprite**（无材质时它渲染整屏粉白）+ 走确定性 Graphics 四带遮罩（drawMaskFallback）；浏览器端保留原 shader 路径 | 根因1 |
| common/component/ScreenEdgeFill.ts（新增） | Canvas 下动态画上/下纯色延伸带（色=内容上下边缘纯色，无缝）；band=(canvas设计高−1334)/2 自适应；相机 clearColor 改内容主色；canvas-resize 自适应 | 根因2 |
| common/manager/GameSys.ts | 场景回调挂载 ScreenEdgeFill（Canvas 节点） | 根因2 |
| settings/v2/packages/project.json | 维持 SHOW_ALL（fitW/fitH=true，同 2.X 原版）；NO_BORDER 方案因主按钮无 Widget 贴边会被裁切而否决 | 适配基线 |

## 四、验证结果（修复后包实测）
- 引导画面：粉白罩消失，内容清晰，镂空半透黑+选框+手势正常显示；`[GUIDE-ALIGN] step=0 target=button_buildings 对齐成功`。
- 延伸带：`[EDGE-FILL] band=166 canvas=1080x2400 design=750x1667`；接缝处像素带色==内容边缘色（218,192,177 / 183,168,168）**完全一致=无缝**。
- 面板巡检：主场景/商店开-翻页-关 全部 ok（mean≈103，无白屏）。
- 启动期：12 次连启 0 白屏；loading 高频采样 0 白帧。
- 浏览器端：预览正常（左右 letterbox 为预览页深色背景，与 2.X 原版行为一致），shader 路径未受影响。
