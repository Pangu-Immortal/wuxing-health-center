# 五星卫生院 三现象根因修复报告（死循环 / 仙界教学空白引导 / 补货重复触发后重启）

日期：2026-10-17　验证环境：Android 模拟器（1080×2400）debug APK　全量日志：/tmp/flow_logcat.log
验证方式：玩家视角全流程脚本 /tmp/flow_test.py（清档→公告→引导 0→32→业务循环→重启持久化），持续采集五类日志：状态机状态（[GUIDE-STEP]/[NewGuide] step）、场景与资源加载（Success to load scene / [POPUP-LOAD]）、引导手势目标与坐标（[GUIDE-DBG]/[GUIDE-ALIGN]）、步骤触发与完成（[GUIDE-STEP] enter/done）、循环与重启触发条件（[SHOP-LOOP]/[GUIDE-WD]/[GUIDE-INIT]）。

## 一、三个现象的根因与修复（逐条对应）

### 现象一：流程死循环
- **根因**：`Shop.onTouchStart` 启动 `schedule(0.05)` 补货循环，**唯一退出是 touch_buy 节点的 TOUCH_END**；而 `PopupBase.hide()` 关闭面板时会挂 `BlockInputEvents` 遮罩吞掉该 TOUCH_END（触点在按钮外结束同样丢失）→ 循环永不停止 = 死循环。
- **修复**（`panel/Shop.ts`）：三重退出——① `onDisable()` 增加 `unscheduleAllCallbacks()`（面板隐藏/停用必停）；② 面板根节点补挂全局 TOUCH_END/TOUCH_CANCEL 兜底停循环；③ 硬上限 400 次（约 20s）强制停。启停均输出 `[SHOP-LOOP]` 日志。
- **实测证据**：`[SHOP-LOOP] start index=0` → 2s 后 `[SHOP-LOOP] stop touch-end count=26`（抬手即停，无死循环）；全程无第二次 start。

### 现象二：进入"仙界教学"提示弹出但界面内容没加载、手势指空白
- **根因**：引导 `continue(v)` **同步**执行 `locateRealTarget(v)` 对齐镂空/选框/手势，但目标面板（商店/仓库/招募等）经 `PopupManager.resources.load` **异步**实例化——绑定时刻目标尚未挂载 → 返回 null → 镂空与手势停在旧位置/空白区，而提示文字（xuankuang Label）已弹出，形成"提示在、内容空白、手势指空"。
- **修复**（`common/component/NewGuide.ts`）：改为**带重试的异步对齐** `alignStep/alignTick`：每 0.25s 重找真实目标，最长 6s；找到即对齐并输出 `[GUIDE-ALIGN] step=N target=… 对齐成功 tries=k`；步骤已前进或超时自动放弃（防悬挂调度）；`onDisable` 清理调度。同时在 `PopupManager.show` 的 resources.load 前后加 `[POPUP-LOAD] start/ok/FAIL` 日志，使"资源加载结果"可观测。
- **实测证据**：step15 `POPUP-LOAD start prefabs/shop → ok`，`GUIDE-ALIGN step=15 target=button_shop 对齐成功 tries=1`；面板类步骤（16/17/19…）在目标确为引导自身按钮时 24 次重试后明确记 `realTarget=none`（有界退出，不悬挂）；全程 `POPUP-LOAD FAIL=0`。

### 现象三：反复测试后同一步骤（补货）重复触发，随后整个流程重启
- **根因（重复触发）**：同现象一的循环无退出——一次长按后循环常驻，后续每次进入商店步骤都叠加触发补货。
- **根因（流程重启）**：① `NewGuide.cachujixu(0)` 在每次 `onEnable` 都把状态机 NEWGUIDECON 重置为 0——引导完成后任何节点重激活（含崩溃重启、面板联动）都会把教学打回第一步；② 历史崩溃源：满级后 `HeadInfo.change_lvl` 的递归 `cb()` 无限递归栈溢出（上一轮已修）导致应用重启、引导重来。
- **修复**：① `cachujixu` 增加守卫——`Caches.newGuide` 为真（引导已完成）时直接 `node.active=false` 返回，**不再重置状态机**；② `onEnable` 绑定前先 `xUnbind(BINDER_NAME)` 去重，防 continue 双绑导致同步骤重复触发；③ 补货循环三重退出（现象一）消除重复触发源；④ 看门狗每次自动推进输出 `[GUIDE-WD] stall 自动推进 a->b`，重启/循环触发条件全程可见。
- **实测证据**：全流程 `GUIDE-INIT 状态机重置 step=0` 仅 **1 次**（首启）；引导 `done step=32` 后再次启动应用，`DBG-STATE … guide=1` 且重置次数仍为 1（不再重启教学）；`SHOP-LOOP start` 全程仅 1 次。
