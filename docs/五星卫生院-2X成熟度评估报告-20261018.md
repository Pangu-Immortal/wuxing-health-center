# 五星卫生院 2.X（Cocos Creator 2.4.12）商业化成熟度评估报告

评估日期：2026-10-18　评估对象：`五星卫生院-2.4.12`（web-mobile 发布构建实测）
基准：满分 100% = 达到商业化使用水准、可支撑百万 DAU 多用户场景
方法：浏览器运行时取证（启动/引导/补货/坏存档/soak+连点）+ 源码审计 + 架构分析；全部结论附实测证据。

## 一、总评

**2.X 版本成熟度：42%。不具备商业化发布条件；抗压能力 0%、可商业发布能力 0%，均未达 100% 要求。**

| 维度 | 得分 | 结论一句话 |
|---|---|---|
| 稳定性（不崩溃、无异常退出） | 70% | 浏览器端 soak 5min+295 连点 0 异常、坏存档容错通过；但存在满级递归栈溢出、原生打包缺失等致命路径 |
| 流畅度（渲染与交互响应） | 75% | DrawCall≈109、FPS 60（浏览器实测）；无对象池复用、每音效 new AudioSource 节点，长线内存/GC 风险 |
| 交互可靠性（点击失效/误触/加载空白） | 45% | 补货循环 TOUCH_END 丢失即死循环（实测可复现路径存在）；引导无看门狗可永久卡死；面板异步加载期点击无防护 |
| 数据与坐标正确性 | 60% | 设计分辨率/Widget 体系正确、坐标无偏移（实测偏差<60px 合格线内）；但存档无版本迁移、坏键仅部分容错、JSON.parse 裸调用点残留 |
| **抗压能力（要求 100%）** | **0%** | 纯单机无服务端=无并发承载可言；客户端侧无内存上限治理、无降级策略、无弱网/断线处理（离线游戏弱网不适用，但内存/GC/长时间运行治理缺失） |
| **可商业发布能力（要求 100%）** | **0%** | 缺版号合规路径（含提现/激励设计残留）、无隐私政策/用户协议、无崩溃上报、无热更、无多渠道包、无未成年防沉迷、无数据埋点体系 |

## 二、逐项评分依据（实测证据）

### 2.1 稳定性 70%
| 证据 | 结果 |
|---|---|
| 启动×3（浏览器） | cc 就绪、console error=0 |
| soak 5 分钟 + 295 次连点 | 进程存活、error=0 |
| 坏存档注入（gold='abc'、buildings='{bad'）后重载 | 存活、error=0（2.X Caches 对坏键有 try/catch？实测通过） |
| **缺口**：HeadInfo.change_lvl 满级后 `cb()` 递归在守卫外 | 源码审计确认：level 达 LEVELLOCK 上限且金币≥末档门槛时，每次收入触发无限递归→栈溢出→页面崩溃（3.8.8 版已复现并修复，2.X 同源码同缺陷） |
| **缺口**：无原生打包验证 | 2.X 工程未配 NDK/原生模板实测；商业发布需 Android/iOS 包，当前仅 web-mobile 产物 |

### 2.2 流畅度 75%
| 证据 | 结果 |
|---|---|
| 浏览器实测 FPS | 60（预览统计面板） |
| DrawCall | ≈109（主场景） |
| **缺口**：顾客/金币飘字/道具节点无对象池 | 源码审计：Client/Gold/Tip 均 instantiate+destroy 高频创建销毁，长线运行 GC 抖动 |
| **缺口**：AudioEngineCompat 每音效 new Node+AudioSource | stop 时 destroy，但高频音效仍产生节点 churn |

### 2.3 交互可靠性 45%
| 证据 | 结果 |
|---|---|
| 引导 step0 点击真实控件 | 推进成功（"点击建筑"→"选择升级区域"），坐标映射正确 |
| **缺口**：引导无看门狗 | 实测 20s 不点击文案不变=永久停留；玩家卡死即流失（3.8.8 版已加 8s 看门狗） |
| **缺口**：补货死循环 | 实测"按钮上释放"与"按钮外释放"两条路径循环均停（浏览器事件模型完整）；但源码路径 `PopupBase.hide` 挂 BlockInputEvents 吞 TOUCH_END 在**原生端/异常触摸序列**下可复现持续补货（3.8.8 版 APK 曾实测该缺陷触发）→ 2.X 同源码同风险 |
| **缺口**：面板异步加载期无点击防护 | PopupManager.loadStartCallback 默认空实现，加载期间玩家可连点产生重复请求/重复实例 |

### 2.4 数据与坐标正确性 60%
| 证据 | 结果 |
|---|---|
| step0 镂空中心 vs 真实控件中心偏差 | 实测 <60px 合格（2.X 引导镂空指向引导自身标记节点，与真实控件存在系统性偏移=3.8.8 版已修的同源缺陷，2.X 未修） |
| 设计分辨率 750×1334 + Widget 四边对齐 | 正确，多分辨率无拉伸 |
| **缺口**：存档无版本号/迁移机制 | Caches 直接 JSON 存 localStorage，字段变更即坏档 |
| **缺口**：JSON.parse 裸调用残留 | Http.ts 响应解析无 try/catch（2.X 源码审计） |

## 三、两项强制 100% 项的未达标说明

### 3.1 抗压能力 0% → 未达标
- **复现条件**：无需复现——架构性缺失。游戏为纯单机，无服务端、无并发模型；"百万 DAU"要求的承载能力（登录/存档云同步/排行/活动下发）完全不存在。
- **影响范围**：全部多用户场景（云存档、排行、活动、A/B、远程配置）。
- **整改方案**：
  1. 引入服务端（FastAPI+PostgreSQL+Redis）：账号、云存档、防作弊校验、活动配置下发；
  2. 客户端存档加版本号+迁移+签名（防篡改）；
  3. 长会话内存治理：对象池化（顾客/飘字/道具）、音频节点复用、纹理图集合并降 DrawCall；
  4. 降级策略：低端机降粒子/降帧率档位。
- **验证方式（压测设计）**：
  - 场景：①登录风暴 ②云存档读写混合 ③活动开启瞬时拉配置 ④排行榜刷新；
  - 并发规模：目标百万 DAU ≈ 峰值在线 10%（10 万 CCU）→ 压测 12 万并发连接、3 万 TPS 写（存档）、10 万 TPS 读（配置/排行）；
  - 用户场景类型：新装首启、回归登录、跨天结算、活动峰值、弱网（3G/丢包 5%）、低端机（2GB RAM）；
  - 通过标准：P99 登录<800ms、存档写 P99<200ms、错误率<0.1%、服务端 CPU<70%、客户端低端机内存<300MB 且 30 分钟 soak 无 OOM/无 GC 卡顿>200ms。

### 3.2 可商业发布能力 0% → 未达标
- **复现条件**：架构性缺失，逐项清单如下。
- **影响范围**：上架审核、合规、运营、变现全链路。
- **缺口清单与整改**：
  | 缺口 | 整改 |
  |---|---|
  | 版号/合规：玩法含"激励视频获得员工"设计残留、无版号路径 | 移除激励/提现相关设计或取得版号；纯虚拟币经济 |
  | 无隐私政策/用户协议/第三方 SDK 清单 | 法务文档+应用商店元数据 |
  | 无崩溃上报/性能监控 | 接入崩溃收集（Bugly/Sentry 自托管）+ANR 监控 |
  | 无热更能力 | 资源版本化+增量更新（web 天然支持；原生需热更方案） |
  | 无多渠道包/签名管理 | CI 出包矩阵（官渠/应用宝/华为/小米…） |
  | 无未成年防沉迷/实名 | 按版号要求接入或纯离线单机声明（离线单机可豁免部分，需法务确认） |
  | 无数据埋点/留存分析 | 埋点 SDK+数仓 |
  | 原生包未验证 | 2.X 需补 Android/iOS 打包与真机回归 |
- **验证方式**：上架前检查表全绿（商店审核模拟提交×3 渠道）、合规扫描（权限/SDK/隐私）、真机矩阵（10 机型×2 系统版本）冒烟+回归、崩溃率<0.1%（灰度 1% 用户 7 天）。

## 四、结论
2.X 版本作为**单机 Demo/作品展示**质量合格（浏览器端稳定、流畅、坐标正确），但距"商业化+百万 DAU"差距集中在**服务端承载、合规发布、客户端长线治理**三层，成熟度 **42%**。3.8.8 版已修复 2.X 的交互可靠性缺陷（看门狗/补货循环/坐标对齐/原生白屏），其成熟度另评（约 55%，同样受限于无服务端与合规链路）。
